Part 1 — Create the project and import assets

Godot 4.7.2. Screenshots are from the real editor and a real run. The end-of-lesson project is 01-start in the attachments.

When you finish this lesson, you will have your own game project: a background filling the view, and a small plane on the left. It will not fly yet. You will have taken the first step from texture files to a game screen.

The course starts from zero. You do not need prior programming. We build the picture first; Part 2 adds scripts to the plane. This article is long. You can pause after importing assets.

1. Prepare the engine and a practice folder

This tutorial uses Godot 4.7.2. If you already have it, start it. If not, get that version from the Godot download archive. Pick the package for your OS and CPU, unzip it, then run the editor.

The course uses GDScript. The standard editor is enough. If you already installed the .NET (Mono) build, keep using it. Do not switch versions just for this lesson. I recorded this on Windows with 4.7.2 Mono. Do not launch the editor from inside an unextracted zip.

Create a separate practice folder, for example D:/GodotLearning/TappyPlanePractice/. Use any drive you have. This folder is for the project you build by hand. Keep it apart from downloaded reference projects.

2. Create the project

Godot opens the Project Manager. Click Create, then fill in:

  • Project name: TappyPlanePractice
  • Project path: the empty folder you just created
  • Renderer: Compatibility
  • Version control metadata: if shown, beginners can choose None

This lesson uses Compatibility for a simple 2D picture. The reference project originally used Forward Plus. That does not stop you from choosing Compatibility in the practice project.

Confirm and open. The 01-start name on the reference zip is only a stage tag. Your project can stay TappyPlanePractice. The folder will contain project.godot. That file stores project settings. When you import an existing project later, pick that file.

3. Know the editor areas you will use

  • Scene — nodes in the current scene
  • Center workspace — view and edit the picture
  • Inspector — properties of the selected object
  • FileSystem — assets, scenes, and scripts

A node is an object with a job, for example a Sprite2D that draws a picture. Organize nodes as parent and child, then save — that is a scene. A scene does not have to be a whole level. One plane can be its own scene, then dropped into the game later.

Learn the names first. The next steps will make them concrete.

4. Import game assets

Each of the three lesson packs already contains an assets folder. You can copy from those. You can also download the TappyPlane reference project. If you do not use Git, use Code → Download ZIP on the repo page. Copy the whole assets folder into your practice project root, next to project.godot.

Copy only assets. Do not copy the reference game.tscn, src, or project.godot. Those are finished scenes, scripts, and settings. Later lessons will have you build them.

Return to Godot and wait until import finishes. FileSystem should look like:

res://
├── assets/
│   ├── audio/
│   ├── fonts/
│   ├── textures/
│   └── default_bus_layout.tres
└── project.godot

res:// means the root of this project. It is not a folder named res on your disk. This lesson uses two images:

  • Background: res://assets/textures/others/background.png
  • Plane: res://assets/textures/entities/planes/planeYellow1.png

Find them in FileSystem and click to preview. Ignore sounds, fonts, and other pictures for now.

The pictures come from Kenney. If you download Kenney’s pack yourself, the folder layout may differ. This lesson follows the paths above.

5. Set the game view size

Open Project → Project Settings. Find Display → Window. You can also search the English property names:

  • Size → Viewport Width: 576
  • Size → Viewport Height: 324
  • Stretch → Mode: canvas_items

Viewport size is the grid you use to place objects. 576×324 means 576 units across and 324 down. The run window can be larger; place objects against this grid first. The attachments set Window Width Override to 1152 and Height Override to 648 so the window shows at 2×. That does not change the 576×324 game coordinates.

In 2D, X grows to the right and Y grows down. Changing (72, 100) to (72, 152) moves the object down.

6. Create the main scene and add the background

In an empty scene, click 2D Scene to create a Node2D root. Rename it Game. Press Ctrl+S and save as game.tscn in the project root.

Select Game, add a Sprite2D child named Background. Select Background, drag background.png from FileSystem onto the Inspector Texture.

Open Transform. Set Position to (288, 162). A centered Sprite2D uses that point as the image center. Put it in the middle of the 576×324 view.

The source background is 800×480. Set Scale X and Y both to 0.72. Display size becomes 576×345.6; the extra top and bottom are clipped by the viewport. Scale the image so it covers the view. Keep X and Y the same to preserve aspect. Use the larger of 576 ÷ image width and 324 ÷ image height. You can read width and height in the texture preview. A little overflow is fine. The important part is no empty edge.

This lesson uses a still background. Scrolling and repeat wait until Part 2, when the background goes under Parallax2D.

7. Create a separate plane scene

Use Scene → New Scene. Choose Other Node, search CharacterBody2D, create it, name it Plane. This root will move later. For now, build the look.

In FileSystem, create src at the project root, then entities inside it. Save the scene as res://src/entities/plane.tscn.

Select Plane and add two children:

Plane (CharacterBody2D)
├── Sprite2D (Sprite2D)
└── CollisionShape2D (CollisionShape2D)

Select Sprite2D, drag planeYellow1.png onto Texture. Leave Position at (0, 0) so the image sits on the plane root.

Select CollisionShape2D. In Shape, choose New CircleShape2D, open the shape, set Radius to 45. The collision shape is for contact later. It will not draw as a picture in a normal play view. You only need to know it exists here. Detection rules come in Part 2 with the rocks.

Select the Plane root. Set Scale X and Y to 0.5. The sprite and shape are children, so they shrink together. Save. This single frame is only a starting look. Part 2 switches to a frame animation and fixes facing.

If CharacterBody2D warns about a missing collision shape, finish the shape above, then check again. The warning does not mean you must write movement code immediately.

8. Put the plane into the main scene

Switch back to game.tscn. Drag plane.tscn from FileSystem under Game in the Scene dock, as a sibling of Background. Do not drop it onto Background as a child.

Game (Node2D)
├── Background (Sprite2D)
└── Plane (instance of plane.tscn)

Select that Plane instance. Set Position to (72, 152). You are moving the instance in the main scene. You do not need to open plane.tscn to change this.

plane.tscn is a template. Dropping it into Game creates an instance. Spawning many rocks later uses the same idea.

Give both reusable scenes matching scripts: select Game and attach game.gd in the project root, turn off the template, keep only extends Node2D. Select the Plane root in plane.tscn and attach src/entities/plane.gd, keep only extends CharacterBody2D. They have no behavior yet. The next lesson fills them in.

Save game.tscn. Plane sits after Background in the tree, so with default draw order it appears in front.

9. Run your project

Press F5. The first time, Godot may ask for a main scene. Choose game.tscn. You should see the background and a still plane on the left. Still is correct: there is no movement script yet.

F6 runs the scene you are editing. Use it later to test the plane or a rock alone. F5 starts from the main scene. If you only see the plane and no background, you probably pressed F6 inside plane.tscn.

Press F8 or the stop button to quit. Some laptops need Fn with function keys. The toolbar buttons work too.

10. Common problems

No assets in FileSystem. Check that it sits next to project.godot, not nested inside an extra folder from the zip. Wait for import to finish.

The node exists but shows no picture. Check Sprite2D Texture. Copying a file into the folder does not assign it.

The plane is hidden behind the background. Check that Plane and Background are siblings, Plane is listed after Background, and you did not change Visibility or Z Index by accident.

Only the plane is on screen. Confirm you ran game.tscn, not plane.tscn alone.

The background does not cover the view. Check center position and scale. Zooming the editor view does not change runtime image size.

Yellow warnings or red errors. Check that the CircleShape2D resource exists, then read the first error. When you ask for help, include the file name, the error text, and the last step you took.

11. Checkpoint

  • You can find the project folder and project.godot, and reopen the project.
  • You can find the background and plane images under assets.
  • You have game.tscn and src/entities/plane.tscn.
  • F5 shows background and plane; F8 stops.
  • You can explain the difference between the Plane instance in the main scene and the plane.tscn template.

Small drill: change only the instance Position in the main scene so the plane moves a little to the right. Save, run, check. Then restore (72, 152) as the shared start for Part 2.

Part 2 continues from this project. You will fill in plane.gd and write GDScript that flies. Keep the scenes and assets. Do not copy a finished game’s scripts early.
