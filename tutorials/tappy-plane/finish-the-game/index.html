Part 3 — Finish the game

The plane already flies and hits obstacles. Players still need three real loops: where a round starts, how many points this round scored, and how to try again. This lesson wires those together, then covers desktop export and extra practice.

Continue from Part 2, or use the 02-flight zip. This lesson ends at 03-complete. Keep the plane, rocks, and GameConfig from Part 2. Replace only the main-scene controller and add UI. UI uses the same Kenney pictures as the reference project. Do not bring in a new art style.

1. State the round in plain rules

You need three states: menu, playing, game over. Scoring has one rule: while playing, add one point each second; after the round ends, stop.

Those rules do not need to know buttons or audio. Create src/rules/game_rules.gd, inherit RefCounted:

class_name GameRules
extends RefCounted

## Pure rules: no nodes, no waiting on sound or animation.
enum State { MENU, PLAYING, GAME_OVER }
var state: State = State.MENU
var score: int = 0

func start() -> void:
	state = State.PLAYING
	score = 0

func tick() -> void:
	if state == State.PLAYING:
		score += 1

func finish() -> bool:
	if state != State.PLAYING:
		return false
	state = State.GAME_OVER
	return true

enum names a small set of states. state: State only accepts that enum. start() begins a round and zeros the score. tick() is one timer beat. finish() tries to end and returns whether the state actually changed.

Why a bool on finish? The same frame can leave the screen and hit a rock. The second finish() returns false, so the outside code does not play the sting twice, clean twice, or show results twice.

This class is not a node. Do not make a scene for it. Do not put it in the tree. It only stores and changes rule data. Hiding UI does not stop scoring. Sound length does not decide when a round ends.

2. Three separate screens

Build menu_form.tscn, game_form.tscn, and popup_game_over.tscn in src/widgets. Each root uses a matching script. Then you can edit one screen without walking the whole main tree.

2.1 Main menu: containers layout; buttons only notify

Root is Control named MenuForm, layout Full Rect. Center a MarginContainer. Inside it: background TextureRect, then VBoxContainer. Top of the VBox: two rows of letter textures. Bottom: vertical buttons.

└── MarginContainer (centered, min width 300)
    ├── TextureRect (UIbg.png)
    └── VBoxContainer

        ├── MarginContainer3 / HBoxContainer (P L A N E)

            └── btn_quit (TextureButton with Label)

Do not fight containers by dragging widgets around. They re-flow children. Use Custom Minimum Size, Size Flags, and Margins. Letter art: assets/textures/widgets/letters. Panels and buttons: widgets/others. Button Texture Normal: yellow_button00.png, Ignore Texture Size on, min size (100, 30). Inner Label: Full Rect, center horizontally and vertically.

You can point LabelSettings at assets/fonts/new_font_variation.tres and add a black outline. The title uses pictures, not a font, so the colored look from the original project stays.

menu_form.gd:

extends Control
class_name MenuForm

signal btn_new_game_pressed
signal btn_quit_pressed

func _on_btn_new_game_pressed() -> void:
	btn_new_game_pressed.emit()

func _on_btn_quit_pressed() -> void:
	btn_quit_pressed.emit()

In the Node signals dock, connect each button’s pressed to those callbacks. The callbacks only forward signals. They do not call new_game on a parent. The menu does not need to know who spawns the plane.

2.2 In-game score: data changing is not the UI counting by itself

New Control root GameForm, Full Rect. Add an HBoxContainer named ScoreContainer at the top. Right-click ScoreContainer → Access as Unique Name so %ScoreContainer works in the script.

Keep the lesson layout: top-center anchors, Offset Left -40, Top 8, Right 127, Bottom 86, Scale (0.3, 0.3). Place one TextureRect inside with number0.png.

Set Mouse Filter to Ignore on GameForm, ScoreContainer, and the digit TextureRects. Score is decoration. It must not steal clicks from the plane.

game_form.gd:

class_name GameForm
extends Control

@onready var score_container: HBoxContainer = %ScoreContainer
const NUMBER_TEXTURES: Array[Texture2D] = [
	preload("res://assets/textures/widgets/numbers/number0.png"),
	preload("res://assets/textures/widgets/numbers/number1.png"),
	preload("res://assets/textures/widgets/numbers/number2.png"),
	preload("res://assets/textures/widgets/numbers/number3.png"),
	preload("res://assets/textures/widgets/numbers/number4.png"),
	preload("res://assets/textures/widgets/numbers/number5.png"),
	preload("res://assets/textures/widgets/numbers/number6.png"),
	preload("res://assets/textures/widgets/numbers/number7.png"),
	preload("res://assets/textures/widgets/numbers/number8.png"),
	preload("res://assets/textures/widgets/numbers/number9.png")
]

func update_score_display(score: int) -> void:
	var digits: String = str(maxi(score, 0))
	# Remove extras first so this loop sees the correct child count immediately.
	while score_container.get_child_count() > digits.length():
		var extra: Node = score_container.get_child(-1)
		score_container.remove_child(extra)
		extra.queue_free()
	while score_container.get_child_count() < digits.length():
		var picture: TextureRect = TextureRect.new()
		picture.mouse_filter = Control.MOUSE_FILTER_IGNORE
		score_container.add_child(picture)
	for index: int in range(digits.length()):
		var picture: TextureRect = score_container.get_child(index) as TextureRect
		picture.texture = NUMBER_TEXTURES[int(digits[index])]

The integer becomes a string, for example 20 → "2" and "0". Then pick textures by index. Each update first fixes child count, then swaps textures.

You cannot only handle “9 becomes 10.” Retrying “100 becomes 0” must remove two pictures. remove_child then queue_free so this loop already sees the right count, without waiting until the end of the frame.

The textures are read-only. Sharing them across digit nodes is fine. You only change each node’s texture property. You do not edit the image resource.

popup_game_over.gd:

extends MarginContainer
class_name PopupGameOver

@onready var score_label: Label = %ScoreLabel

signal quit_pressed
signal retry_pressed

func update_score(score: int) -> void:
	score_label.text = "Score: " + str(score)

	quit_pressed.emit()

Connect BtnQuit.pressed and BtnRetry.pressed to those callbacks. update_score only displays a number. It does not measure survival time.

2.4 Matching the screenshots exactly

The notes above are enough to build and understand the tree. To match screenshots, finish the three scripts first, then copy the three .tscn files from 03-complete/src/widgets into the same paths in your practice project. Copy only those three scenes. Do not overwrite the whole practice project.

The scene files keep exact container values, letter colors, texture refs, and inner button signals. You can still open and edit every node. The zip is not a locked picture. If you build by hand, node names and signal callbacks must match the scripts.

3. Put UI and the world under different parents

Back in game.tscn. Under Game, add a CanvasLayer named UICanvasLayer, Layer 64. Instance the three UI scenes under it. Start GameForm and PopupGameOver with Visible off.

Add ScoreTimer: Wait Time 1, One Shot off, Autostart off. Add AudioGameOver: Stream assets/audio/sound/gameover2.ogg, Bus SFX, Autoplay off.

Game
├── World
│   ├── Parallax2D / Background
│   └── Actors
├── SpawnTimer
├── AudioBgm
├── ScoreTimer
├── AudioGameOver
└── UICanvasLayer
    ├── MenuForm
    ├── GameForm
    └── PopupGameOver

World is the play space you can freeze as a whole. UI and timers are siblings. On game over we stop World processing and stop both timers; UI still responds. That is easier to explain than pausing the entire tree and then un-pausing buttons one by one.

4. Connect one round in the main script

Replace all of game.gd. Do not keep Part 2 _restart(), restarting, or a _ready() that auto-starts a round. Game Config is still default_game_config.tres.

extends Node2D

const PLANE_SCENE: PackedScene = preload("res://src/entities/plane.tscn")
const ROCK_SCENE: PackedScene = preload("res://src/entities/rock.tscn")
@export var config: GameConfig
@onready var world: Node2D = $World
@onready var actors: Node2D = $World/Actors
@onready var spawn_timer: Timer = $SpawnTimer
var plane: TappyPlane

@onready var score_timer: Timer = $ScoreTimer
@onready var menu_form: MenuForm = $UICanvasLayer/MenuForm
@onready var game_form: GameForm = $UICanvasLayer/GameForm
@onready var popup_game_over: PopupGameOver = $UICanvasLayer/PopupGameOver
@onready var audio_game_over: AudioStreamPlayer = $AudioGameOver
var rules: GameRules = GameRules.new()

#region Lifecycle
func _ready() -> void:
	spawn_timer.timeout.connect(_on_spawn_timeout)
	score_timer.timeout.connect(_on_score_timeout)
	menu_form.btn_new_game_pressed.connect(new_game)
	menu_form.btn_quit_pressed.connect(quit_game)
	popup_game_over.retry_pressed.connect(new_game)
	popup_game_over.quit_pressed.connect(quit_game)
	menu_form.show()
	game_form.hide()
	popup_game_over.hide()

func _process(_delta: float) -> void:
	if rules.state == GameRules.State.PLAYING and is_instance_valid(plane):
		if plane.position.y <= 0.0 or plane.position.y >= get_viewport_rect().size.y:
			_on_hit()
#endregion

#region Public
func new_game() -> void:
	_clear_actors()
	rules.start()
	world.process_mode = Node.PROCESS_MODE_INHERIT
	menu_form.hide()
	popup_game_over.hide()
	game_form.show()
	game_form.update_score_display(rules.score)
	_spawn_plane()
	_schedule_rock()
	score_timer.start()

func quit_game() -> void:
	get_tree().quit()
#endregion

#region Signals and spawn
func _on_hit() -> void:
	if not rules.finish():
		return
	spawn_timer.stop()
	score_timer.stop()
	world.set_deferred("process_mode", Node.PROCESS_MODE_DISABLED)
	audio_game_over.play()
	game_form.hide()
	popup_game_over.update_score(rules.score)
	popup_game_over.show()
	_clear_actors.call_deferred()

func _on_spawn_timeout() -> void:
	if rules.state == GameRules.State.PLAYING:
		_spawn_rock()
		_schedule_rock()

func _on_score_timeout() -> void:
	rules.tick()
	game_form.update_score_display(rules.score)

func _spawn_plane() -> void:
	plane = PLANE_SCENE.instantiate() as TappyPlane
	plane.config = config
	plane.position = config.plane_start
	actors.add_child(plane)

func _spawn_rock() -> void:
	var rock: Rock = ROCK_SCENE.instantiate() as Rock
	rock.config = config
	rock.rock_entered.connect(_on_hit)
	if randi_range(0, 1) == 0:
		rock.position = Vector2(config.spawn_x,
			randf_range(config.bottom_y.x, config.bottom_y.y))
	else:
		rock.rotation_degrees = 180.0
		rock.position = Vector2(config.spawn_x,
			randf_range(config.top_y.x, config.top_y.y))
	actors.add_child(rock)

func _schedule_rock() -> void:
	spawn_timer.start(randf_range(config.spawn_interval.x, config.spawn_interval.y))

func _clear_actors() -> void:
	for actor: Node in actors.get_children():
		actors.remove_child(actor)
		actor.queue_free()
	plane = null

#endregion

Read it in run order

First _ready() only connects signals and shows the menu. No plane yet. “New Game” makes MenuForm emit; Game runs new_game: clear old actors, reset rules, restore World, switch UI, spawn the plane, start spawn and score timers.

SpawnTimer timeout only makes rocks. ScoreTimer timeout calls rules.tick(), then GameForm displays the score. The UI does not run its own score timer.

Collision or leaving the view both go to _on_hit(). rules.finish() must succeed first. Then stop timers, defer-disable World, play the sting, show results. set_deferred() and call_deferred() on cleanup matter: a real hit can arrive inside a physics callback. Disabling a collider in that moment errors.

Retry still calls new_game. The new plane has its own zero velocity and spawn point. You do not patch a plane you already freed.

Connect each signal once

  • Menu buttons pressed — connect in menu_form.tscn to the menu callbacks
  • Result buttons pressed — connect in popup_game_over.tscn to the popup callbacks
  • MenuForm custom signals — connect in Game._ready to new_game / quit_game
  • PopupGameOver custom signals — connect in Game._ready to new_game / quit_game
  • SpawnTimer / ScoreTimer timeout — connect in Game._ready to the two timer callbacks
  • Rock.body_entered — connect in rock.tscn to Rock’s own check
  • Rock.rock_entered — connect each time you spawn a rock to Game._on_hit

If the table says “in code,” do not also connect it in the editor. One click would start two rounds; one tick would add two points.

Pitfall: Retry does nothing if you pause the whole tree

The lesson script above freezes play by setting World.process_mode to disabled. UI stays a sibling, so buttons still work.

Some shipped demos instead call get_tree().paused = true. A CanvasLayer inherits pause by default, so PopupGameOver is visible but never gets pressed.

If you use tree pause, set UICanvasLayer.process_mode to PROCESS_MODE_ALWAYS (3) so the results layer still processes while the tree is paused. Pause and ALWAYS must travel together. The lesson code does not need that pair unless you switch to get_tree().paused.

5. Play: menu through retry

Start a game. Hold height with Space or left click. Watch the score rise once per second. Time scoring does not require passing a rock. Then stop flapping and let the plane leave the view.

The result score must stay still. Background scroll stops. Both buttons still click. Retry: score back to 0, one plane, no rocks from the last round.

Play at least three rounds. Then force: leave the top, leave the bottom, hit a rock. All three should reach the same results screen. If score jumps too fast, look for double signal connections. If Retry does nothing, look for leftover get_tree().paused = true without ALWAYS on the UI layer. If extra digits remain, check that the update function removed extra nodes.

6. Export for people who do not have the editor

Running from the editor and exporting are different jobs. Export builds a program and data you can hand to someone else.

  1. Save every scene. Editor → Manage Export Templates and install templates that match 4.7.2 (or whatever editor you actually use). For Windows pick x86_64. Chinese locale installs may also need ICU Data from the template manager. On a Mono editor, watch the export panel’s Mono template path. Do not mix versions.
  2. Project → Export, add Windows Desktop. Architecture should match the target PC. Typical Intel/AMD Windows is x86_64.
  3. Resources: Export All Resources. This practice project is the game only. Do not pack paid articles or screenshots into the game.
  4. Export to a separate folder, for example exports/TappyPlane.exe. Fix missing-template warnings. Do not ignore red rows.
  5. Use Export Project. Export PCK/ZIP is only a data pack. It is not a double-clickable game.
  6. Close the editor. Launch the exported program. Recheck start, score, fail, retry, quit. If a .pck or other sidecar files appear, ship them together.

The zip with this lesson is a run-checked source project. It does not claim your PC already has export templates. If a screenshot shows missing templates, that is the environment you still need — not a finished retail build. See Exporting projects.

Case-sensitive paths: Windows editor ignores rock.tscn vs Rock.tscn. The exported .pck does not. Keep preload() paths identical to filenames. After export, run the console exe once and look for Preload file does not exist.

7. After you finish, pick one extra task

Close the article. From memory, name four things: who spawns the plane, who detects hits, who stores the score, who shows the score. Explaining how methods and signals share work is more useful than reciting the whole script.

Rebuild from an empty project: plane, one obstacle, fail, retry. Same art is allowed. Do not copy the finished project wholesale.

Then pick one extra:

  • Save high score — survives restart; a lower score cannot overwrite
  • Ramp difficulty — parameters have a cap; layout stays passable
  • Swap plane looks — two instances can differ; feel stays the same; changing A does not mutate B’s unique resources
  • Score for passing rocks — each rock counts at most once; no points after the round ends

The fourth task changes the original scoring rule. Write the new rule down before you edit. When you are done, share a short clip, a short implementation note, and one bug you found and fixed.

The project is small, but it is a full game loop. When you add high scores, difficulty, or new looks, keep the same split: rules store data, objects do their job, UI shows the result.
